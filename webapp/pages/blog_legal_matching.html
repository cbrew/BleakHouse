Optimal Transport for Legal Document Matching

When min-cost flow beats greedy heuristics for complex information retrieval

Part 13 of the Not In Our Time series

Note: This post describes the matching algorithm that inspired the transport-based selection in the Not In Our Time project.

The Matching Problem

After enriching legal documents, we have source sentences with provisions and target report sections with needs. The goal is to match sources to targets so that every target's needs are satisfied. A greedy approach — finding the best source for each target individually — fails because it leads to over-assignment (one "popular" sentence cited repeatedly) and poor overall coverage.

The Optimal Transport Solution

We reframed matching as a resource allocation problem: sources have supply, targets have demand, and we need to find the minimum-cost way to satisfy all demand. This is a classic min-cost flow problem. Each (section, dimension) pair becomes a separate flow problem, ensuring global optimization and explicit gap detection.

The Flow Network

For each (section, dimension) pair, we construct a flow network with a super-source, a super-sink, and a NULL node. Arcs from real sources have low costs (1 for strong matches, 2 for weak), while the arc from the NULL node has a very high cost (100). The solver (Google OR-Tools) minimizes total cost, meaning it will only use the NULL node when no real sources can satisfy the demand.

Gap Detection: NULL Flows

The magic is in the NULL node. When real sources can't satisfy demand, flow must come from NULL. The amount of flow through the NULL node is the precise measure of the gap. No arbitrary thresholds are required — the gap is exactly the amount of unmet demand.

Why This Beats the Heuristic Approach

We replaced a 4-stage heuristic pipeline (filtering, scoring, BM25, and LLM verification) with a single optimization pass. The results are deterministic, faster, and cheaper because they remove the LLM from the matching loop. In a typical case, runtime dropped from 45 seconds to 0.3 seconds with zero API cost and improved coverage.

Semantic Direction

To prevent matching sentences with identical dimensions but opposite meanings (e.g., "Defendant owed a duty" vs "Defendant owed no duty"), we added SemanticDirection. This metadata captures legal stance and party alignment, ensuring that sources are only matched to targets with compatible semantic intent.

Key Takeaways

  • Model matching as resource allocation, not similarity search.
  • Solve per (section, dimension) to keep problems small and fast.
  • NULL flows provide exact, threshold-free gap detection.
  • Deterministic algorithms like min-cost flow beat greedy LLM-in-the-loop heuristics.

This approach — using mathematical optimization to bridge the gap between structured metadata and editorial requirements — is the core technical innovation that makes both the legal pipeline and the literary podcast possible.
