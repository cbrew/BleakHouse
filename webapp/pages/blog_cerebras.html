Speed and Structure: Generating Scripts with Cerebras

Adapting an Anthropic structured-output pipeline to an ultra-fast API

Part 14 of the Not In Our Time series

The Not In Our Time pipeline relies heavily on Anthropic's Claude models. From passage enrichment (Phase 0) to script generation (Phase 3), the architecture depends on Anthropic's strict adherence to complex Pydantic schemas via the .messages.parse() endpoint. The multi-voice script generator alone processes ~100,000 tokens of context per episode, returning a JSON array of carefully timed utterances.

But what happens when you want to drastically accelerate that iteration loop? We experimented with swapping our core generation engine to Cerebras, exploring how a high-speed, OpenAI-compatible endpoint handles deep literary context and rigid structured output.

The Candidates

The experimental branch tested three massive open-weights models running at Cerebras's signature inference speeds:

  • Qwen-3 235B (cerebras_qwen)
  • Z.ai GLM 4.7 (cerebras_zai_glm)
  • gpt-oss 120B (cerebras_gpt_oss)

The Engineering Challenges

Swapping a tightly-coupled Anthropic pipeline to an OpenAI-compatible API is not a trivial drop-in, especially when the entire downstream TTS engine depends on perfect JSON schema adherence.

1. The Structured Output Gap

Anthropic's .messages.parse() natively enforces our ParagraphEnrichment and script utterance schemas. Cerebras's API is shaped like standard chat completions. To adapt the pipeline, we had to build a structured-output proxy—relying on JSON mode and rigorous client-side validation to ensure that the rapid-fire responses didn't break the strict utterance types, quote modes, and pause timings required by the TTS renderer.

2. The Batching Problem

Phase 0 (Enrichment) processes 60,000 passages across 15 novels. The original architecture relies on Anthropic's asynchronous Batch API to make this cost-effective and manageable. Cerebras does not currently offer an equivalent batch API. However, the sheer token-per-second speed of Cerebras inference makes synchronous, multi-threaded calls a viable alternative to asynchronous batching.

3. No Embeddings

Cerebras focuses on text generation and does not offer embedding models. This meant our contextual retrieval pathway (Phase 1) could not be ported. The Cerebras integration is strictly an adapter for the generative phases: Phase 2.5 (Host Preparation) and Phase 3 (Script Generation).

The Results

Despite the architectural friction, the integration succeeded. We generated complete Bleak House episodes across the Literary, Alternative, and Interdisciplinary panels using the Cerebras-hosted models. The results are logged in dedicated experiment matrices (e.g., run_tracker_cerebras_qwen.html).

The primary takeaway is architectural flexibility: a complex, multi-stage pipeline built around one provider's proprietary structured output features can be abstracted. By moving the validation logic to the client side, we unlocked the ability to throw massive context windows at ultra-fast inference engines. The models successfully navigated the complex task of multi-voice character impersonation, quote weaving, and prosodic annotation, proving that you don't have to sacrifice speed for structure.
