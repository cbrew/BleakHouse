Building This With Claude Code

What it's like to build a research project through conversation

Part 8 of the Not In Our Time series

This project was built almost entirely through conversation with Claude Code. The pipeline, the experiment orchestration, the webapp, the paper drafts, the blog posts you're reading, and this site — all produced in extended sessions where a human provided direction and Claude Code wrote the code, ran the experiments, and deployed the results.

The workflow

Issue tracking uses Steve Yegge's Beads — a git-backed issue tracker designed for multi-session AI work. At the start of each session, Beads restores the context: what's done, what's in progress, what's blocked. At the end, open issues persist for the next session.

The development pattern follows what Simon Willison describes as agentic engineering: the human sets direction, the agent proposes and executes, the human evaluates and corrects. Small commits, frequent pushes, test locally before deploying.

What Claude Code is good at

Parallel exploration. When we needed to understand the data — how many nop quotes are verified by novel, what the within-author gradients look like, whether host prep affects confabulation — Claude Code ran dozens of analysis scripts in minutes. The three-document dialectic (thesis, rebuttal, synthesis on the analytical reinforcement hypothesis) was produced in a single session.

Pipeline orchestration. The 180-run matrix was orchestrated by a script that Claude Code wrote, tested, and ran. When 11 runs failed (the crash before the matrix was complete), it diagnosed the failures, identified the resume-from strategy, and completed the remaining runs.

Systematic refactoring. Moving manifest generation into the pipeline (Phase 4), saving pre-interviews to disk, fixing the BH path bugs across four files — these are the kind of mechanical changes that benefit from an agent that can grep, edit, test, and commit without losing context.

What Claude Code is bad at

Making claims without evidence. We instituted a "no unsupported claims" policy early on, and it was needed constantly. Claude Code would assert that Cranford has "a longer history of classroom use" than North and South (it doesn't — we checked), that the fog opening appears "across hundreds of sources" (plausible but unmeasured), or that a correlation of 0.89 "explains 79% of variance" (true but misleading with n=15 and an excluded outlier). Each of these required catching and correcting.

Knowing when to stop. Left to its own devices, Claude Code will add error handling, type annotations, docstrings, and "improvements" to code that doesn't need them. The instruction to avoid unnecessary changes has to be repeated.

Fly.io deployment. The audio volume upload saga — multiple failed sftp attempts, machines auto-stopping mid-transfer, volumes being per-machine not per-app — required real debugging. The eventual solution (tar pipe through ssh) was found through trial and error, not through Claude Code's prior knowledge.

The no-unsupported-claims policy

This is worth its own section. The policy: do not state things as fact without evidence. This covers literary claims (use enrichment data, not intuition), technical claims (check file sizes, read code), and causal explanations (report correlations, don't invent mechanisms). Post-hoc rationalisation is explicitly prohibited.

The policy was needed because Claude Code's default mode is confident assertion. It produces fluent, plausible-sounding claims that turn out to be wrong. The pastiche finding is ironic: the same mechanism that makes the LLM produce plausible-but-nonexistent Dickens quotations also makes it produce plausible-but-unsupported analytical claims. In both cases, the words are real but the sequences are invented.

The human's role

Direction-setting. Error-catching. Editorial judgement. The human decides what questions to ask ("what if I put my friends in the podcast?"), catches errors ("that claim about classroom use is speculative"), and makes editorial calls ("the convergence paradox isn't very paradoxical — just call it framework dominance").

The code is at github.com/cbrew/BleakHouse. The commit history shows the collaboration — human direction in the prompts, Claude Code execution in the diffs.
