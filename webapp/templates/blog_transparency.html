Transparency About Authoring

How we track and disclose what was written by whom

Part 9 of the Not In Our Time series

This website has a problem that most websites don't: almost all of the text you're reading was written by an AI. The pipeline code, the experiment orchestration, the blog posts, the research summaries, the help text, even this sentence — all produced by Claude Code in conversation with a human director. The human set the direction, caught errors, made editorial calls. But the prose was drafted by the machine.

For a project about LLM-generated literary discussion, this creates an uncomfortable recursion. The system generates podcast scripts that we analyse for quote fidelity — and the analysis itself is generated by the same kind of system. If we're going to be honest about the podcasts' provenance (which is the whole point of the prompts page and the passage backlinks), we should be equally honest about the website's provenance.

What we did

Every page on this site has a coloured badge at the bottom, just above the feedback bar. The badge says one of:

  • AI-drafted — Claude Code wrote it, and the git history does not show explicit evidence of substantial human wording changes.
  • AI-drafted, human-directed — Claude Code wrote it, but the human provided substantial editorial direction: restructuring the page, requesting specific content, correcting claims, or renaming sections.
  • AI-drafted, human-edited — the commit history contains explicit user-edit signals, but not enough page-level evidence to say the final wording is mostly human.
  • Effectively human-written — a conservative heuristic says most of the current page text comes from commits explicitly marked as user or human edits, and that signal appears in the latest revision or in repeated revisions.

Each badge links to the file's GitHub commit history, so anyone can verify the claim by reading the diffs.

How it works

A Python script (scripts/generate_provenance.py) runs at staging time and examines the git history for each page file. It counts commits, checks for Co-Authored-By trailers that mention Claude, cross-references against a list of pages where the human provided significant direction, and scans commit messages for explicit user-edit signals. For the green badge, it also uses git blame to ask how much of the current page text comes from those human-signalled commits.

The result is a JSON file (provenance.json) served as a static asset. The shared navigation script (nav.js) fetches it and injects the appropriate badge on each page.

What it doesn't capture

The badge system has real limitations:

All commits go through Claude Code. Even when the human edits a file directly in the IDE, the change is typically committed by Claude Code in the next interaction. The git history shows Claude Code as the author of every commit, with the human's role visible only in the commit messages ("per user edits", "user directed", etc.) and in the conversation logs that aren't public.

"Human-directed" is a judgement call. The script uses a hardcoded list of pages where the human provided significant direction. That list was assembled from the available conversation evidence. It could be wrong. A page marked "AI-drafted" might have had more human input than we captured; a page marked "human-directed" might have had less.

Intellectual contribution isn't captured by line counts. The human's most important contributions — "that claim is speculative", "the convergence paradox isn't very paradoxical", "musicologist is within the humanities" — are single sentences that redirect entire sections. They may not produce large diffs. The git history captures the what better than the why.

The podcast scripts are excluded. The generated literary discussions, host preparation data, and passage backlinks are all fully AI-generated. We don't badge them because their provenance is self-evident — they're the output of the pipeline, not editorial content.

Why it matters

The question of who wrote what is going to become increasingly important as AI-generated text proliferates. For academic work, the distinction between "AI-drafted", "human-directed", "human-edited", and "effectively human-written" matters — not because one is better than another, but because readers deserve to know what kind of quality control and authorship signal was actually present.

Our approach is imperfect. The badges are heuristic, the categorisation is coarse, and the evidence trail (git history plus commit-message signals) captures mechanics better than intention. But it's better than nothing, and it is better than claiming straightforward human authorship for text that a machine drafted.

The previous post describes the no-unsupported-claims policy we applied during development. The provenance badges are the public-facing version of the same principle: if we're going to make claims about text, we should say where the text came from.
