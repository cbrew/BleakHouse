# Open-weight BleakHouse pipeline: current state

**Status:** snapshot 2026-05-16. The live plan is tracked in bd under
**BleakHouse-o3ir** (parent epic) and its children. This document is a
narrative summary; for executable next steps see bd.

The earlier version of this doc (2026-05-14) described a forward-looking
"Stages A–G" migration plan. Most of Stage A (seam migration) has since
landed via the **otae** ticket series — so the original plan is no longer
a faithful description of what remains. This version replaces it.

## Acceptance criterion

**A working novel→script pipeline where every non-embedding phase is
routed to an open-weight ModelSpec, alongside the existing Anthropic
production default.** Co-equal alternatives, not replacement. The
`--pipeline embedding` and `--pipeline no-passages` variants are
explicitly deferred — they are ablations, not serious alternatives.
See user-policy memory `project-open-weight-pipeline-scope`.

### Empirical evidence (closed benchmarks)

- **1aav** (Tier S listener_pick): Llama 3.1 8B / Nemotron-Nano-9B-v2 /
  Gemma 3 4B all rate 2.0–2.38 vs Haiku 4.5 at 3.5 on a 1–5 rubric
  (Haiku-as-judge). Decision: keep Haiku 4.5 for listener_pick.
- **qn0g** (Tier M-Haiku passage_enrichment): Qwen 2.5-72B on DeepInfra
  hits 67% schema validity (1/3 chapters timed out at 30 min);
  Llama 3.3-70B-Turbo hits 0% (markdown-wrapped pseudo-JSON, wrong field
  names). **passage_enrichment is the demonstrated open-weight blocker
  on DeepInfra's strict=False configuration.**

## Production call sites still on raw anthropic

Per `grep` 2026-05-16:

- `submit_passages_enriched.py` — uses Anthropic's native
  `messages.batches` API (50% off, 24h SLA). Not yet exposed by the seam.
- `submit_passage_contexts.py` — same shape, same blocker.
- `reference_tools.py` — partial; verify which call sites moved through
  otae and which didn't.
- `precompute_quote_verification.py` — synchronous structured call;
  cheap to migrate.
- `context_prompt.py`, `collect_*`, `retry_failed.py` — read/unpack
  paths, not LLM call sites; no migration needed.
- `embedding_podcast.py` — embedding variant, deferred per scope.

The load-bearing remaining migrations are the two `submit_*` modules.
Both depend on either (a) a seam batch surface that talks to non-Anthropic
providers, or (b) an explicit sync+concurrency fallback for open-weight
runs. **Tracked as BleakHouse-o3ir.1.**

## Open empirical questions

Three open bd tickets, all P2, all in scope of o3ir:

1. **BleakHouse-dbok** — multi-turn tool-use on open-weight hosts
   (DeepInfra, Together, Cerebras). The seam has tool-use loops; otae
   validated them on OpenAI. Whether open-weight 30B–235B models can
   reliably run the Phase 2.5a tool loop is **the gating question for
   the acceptance criterion** — if no candidate passes, the criterion is
   unreachable without scope change.

2. **BleakHouse-5cjo** — passage_enrichment retry on Together (strict=True
   hosting) or self-hosted vLLM with `guided_json`. Follow-up to qn0g's
   DeepInfra failures. If both fail, escalate.

3. **BleakHouse-bi7w** — methodology decision for Tier L (judging prose
   when Sonnet is both baseline and a candidate judge). Decision-only;
   gates **dll8** (Tier L prose: Gemma 4 / DeepSeek-V3.2) and **ubpm**
   (Tier M-Sonnet host_prep_brief: DeepSeek-V3.2 / Qwen 2.5-72B).

## Headline acceptance ticket

**BleakHouse-o3ir.2** — end-to-end open-weight proof run on North & South.
Blocked by: dbok, 5cjo, ubpm, dll8 (via bi7w), o3ir.1 (batch surface).

## Candidate models (working hypothesis)

Confirming model picks is the job of dll8 / ubpm / 5cjo / dbok; this is
the prior:

- **Phase 3 + 2.5c writer-tier:** DeepSeek-V4-Pro (1st-party promo, MIT)
  as challenger; Qwen3-235B-A22B (Cerebras preview, Apache 2.0) as
  user-validated baseline. gpt-oss-120B as the Apache-2.0 / multi-provider
  resilience option.
- **Small structured (Phase 0 / 2.5b / 4 / passage_contextual):**
  gpt-oss-120B with `reasoning_effort: "low"`. Apache 2.0, 22 providers,
  cleanest schema-feature profile in `docs/structured_output_review.html`.
- **passage_enrichment (after per-paragraph restructure if needed):**
  gpt-oss-120B or DeepSeek-V4-Flash — both passed per-paragraph probes in
  earlier sessions; failed on DeepInfra at the current per-chapter shape.
- **Phase 2.5a tool loop:** whichever survives dbok. Prefer DeepSeek-V4-Pro
  or gpt-oss-120B if multiple pass.

## Risks and unknowns

- **Phase 2.5a on open weights may have no viable candidate.** This is
  the single biggest unknown; dbok is structured to surface this early.
  If true, the acceptance criterion has to be revisited (the user has
  ruled out dropping host-prep as an "ablation").
- **passage_enrichment may need call-shape restructure.** The current
  per-chapter shape doesn't fit DeepInfra-hosted open-weight candidates.
  5cjo's strict=True / vLLM `guided_json` retry decides whether shape
  change is needed at all. If it is, the restructure is ~1 week of work.
- **Cerebras preview-model volatility.** `cerebras_qwen` and
  `cerebras_zai_glm` are preview offerings on Cerebras; either could be
  deprecated. Mitigations: Anthropic default unaffected; `cerebras_gpt_oss`
  is the same-provider Apache-2.0 fallback; gpt-oss-120B has 22-provider
  hosting if Cerebras itself becomes unreliable.
